# 萌宠世界内容主题迁移 · 1.1.0

本轮把三章的可见名称改为“萌宠巴士”“萌宠食堂”“呼噜午睡屋”，为90道主线、14道每日题、20道储备题分别重写标题、开场故事与设计意图，并同步条件卡和纪念卡文案。每道题有独立故事，使用当前 `src/ui/animals.js` 的实际稳定物种和原昵称，例如“小猫小满”。不是给每题统一加一个“萌宠”前缀。

这是独立的动物生活文案及配套视觉主题更新。UI绘制由另一工作范围负责；本次没有增加食物偏好、食物相克、体型占座、物种亲疏、噪声数值、睡意或饥饿值机制。故事里的餐碗、围兜、小包、玩偶与枕头不占用逻辑座位，也不新增约束。所有胜利条件仍来自现有六种规则。

## 身份与存档合同

章节ID仍为 `bus/garden/cinema`。内容版本为 `1.1.0`，所有关卡的 `revision` 保持原值1；日题周期锚点仍为 `2026-09-15`，主线、每日和储备ID及清单顺序均不变。

逐题保留座位ID、坐标、标签、区域、横向邻接边、人物ID、昵称、颜色、人物顺序、规则类型和参数、参考解，以及其他非文案元数据。仅替换 `title/intro/rule.text/designIntent`。因此已有座位安排在本轮仍表达同一道谜题；规则冲突、满足和通关判定不因故事改变。

`content/authoring/legacy.json` 是历史冻结快照，保持字节不变。旧内容的显示文字有意迁移，兼容测试改为比较原几何、人物身份与规则语义、参考解，不再要求旧标题/开场/条件文字逐字相等。新增测试另保存迁移前全部124题去除可变文案后的SHA-256摘要，防止顺手改变任何其他字段。

## 显示术语与逻辑值对应

| 内部标签/区域值 | 本轮显示文字 | 范围保持不变 |
| --- | --- | --- |
| `window` / `door` | 靠窗 / 车门旁 | 巴士每排左端；第一排右端 |
| `front/middle/back` | 第一排/中间排/最后一排；区域仍用车厢前排/中排/后排 | 原有排号或区域 |
| `shade` | 遮光位 | 食堂每排左端；午睡屋第二排左起两席，不能扩展到第三排 |
| `serving` | 取餐位 | 食堂每排右端 |
| `lantern` | 暖灯旁 | 食堂第二排左起第二席 |
| `screen` | 晨光区 | 午睡屋第一排；标签与同名区域各保留原条件 |
| `speaker` | 轻音乐旁 | 午睡屋每排右端；不新增声源范围或噪声数值 |
| `garden` 区域 | 窗边区 | 食堂第一排，不能与巴士 `window` 标签混用 |
| `kitchen` 区域 | 取餐侧 | 食堂其余排，不等于只允许右端的 `serving` 标签 |
| `rear` 区域 | 里侧窝 | 午睡屋非第一排的原有座位 |
| `left/center/right/edge`、`row1/row2/row3` | 每排左端/非两端/右端/两端、具体排号 | 不改变长短排的几何含义 |

`adjacent/apart` 的条件文案指出目标伙伴的真实物种与昵称；“不相邻”没有被改写成“必须不同排”。`emptyNeighbor` 仍明确写“左右至少留一个相邻空位”，没有变成一位动物占两格或根据体型自动留空。所有人都遵循同一套规则，不根据物种凭空推断行为。

## 动物身份与逐题故事

物种由 `animalProfile(person)` 决定，优先使用UI已有的固定昵称映射，其他昵称使用其稳定回退算法。作者端没有复制另一份物种表，也没有把姓名改成物种名。原有12位新增内容角色及历史人物都保留；例如保留“安姨”，不会为凑齐物种而把其改成“阿麦”。物种只是视觉身份，不保证12个昵称恰好各对应一种不同物种。

巴士故事包括爪印车票、纸风车、项圈小章、同行合影与小行李；食堂围绕餐碗、餐垫、暖灯与结伴用餐；午睡屋围绕哈欠、软枕、遮光帘、晨光和轻音乐。开场把故事与真实位置说明分开，作者设计意图继续保留原题的具体推理点，例如长链只能容纳在长排、同一空席供两位伙伴共同邻接、双相邻迫使伙伴落在非端点。

12条纪念卡沿用原ID、阈值和章节归属，只更新名称为动物世界的同行、开饭和午安回忆。`src/core/hints.js` 经检查没有旧场景名，保持原有提示逻辑及通用显示文案。

## 作者源与构建交接

- `content/authoring/levels.json`：当前124题的完整主题内容。
- `content/authoring/design-cards.txt`：94道新增题的原布局/约束卡保留，替换标题/设计意图，新增第9栏独立故事。`{0}`、`{1}`等占位符只展开为对应人物的真实物种＋昵称，不生成新条件。
- `content/authoring/compose.js`：内含30道历史题的文案覆盖层；读取冻结历史后在内存中替换文字。新增题从设计卡展开。两条路径均使用当前动物身份函数与同一套严格条件文字。
- `content/manifest.json`：版本1.1.0及三章新名称；清单成员、顺序、锚点和章节颜色保留。
- `scripts/validate-content.js`：发布版本白名单明确接受 `1.0.0`、`1.1.0`，继续拒绝未知版本和不规范版本。没有删除版本检查，也没有放松90/14/20数量门槛。

`node content/authoring/compose.js` 可重新生成作者JSON与清单，结果与本轮直接交付的JSON一致；它不会改写冻结历史。正常构建仍读取作者JSON，不要求每次运行compose。

编辑器与运行时文件由主任务构建。本次不写共享工作区的generated/runtime文件。内容构建回归在临时目录执行，确认发布清单只导出104道主线/每日题，保留1.1.0版本并剔除储备题、参考解和设计意图。

主题测试独立扫描124题标题、开场、设计意图、条件文字、章节与纪念卡名称，排除旧场景词；另对每条规则的准确显示文字及关系对象逐项断言。历史冻结文件和术语转换代码中的旧词不属于当前可见内容，不能为消除全文搜索结果而篡改历史记录。真实引擎仍验证全部参考解、独立求解及前向提示路径。

这些检查证明的是文案迁移与原谜题合同一致，不代替最终UI联调、手机文字可读性、专业美术或用户盲测。`manualPhoneQA` 保持pending；既有1.0.0自动验收报告不能冒充本轮新报告。

## 后续可独立评估的方向

1. 先把每个稳定昵称的动物形象、剧情称呼和UI头像做跨关核对，评审关系卡中“物种＋昵称”的长度和可读性。
2. 为食堂、巴士和午睡屋分别设计小碗、行李和枕头的装饰变化，但继续明确区分装饰与逻辑标签，避免让玩家猜测隐藏规则。
3. 若未来确实增加食物、体型或其他机制，应先单独设计规则说明、编辑器字段与教学，再创建新关卡或明确提升受影响关卡revision，测试旧存档迁移；不能通过这次换文案偷偷改变既有关卡。
4. 未来可以用盲测记录各物种头像的辨识度、关系条件误读和实际完成时长，再调整叙事与难度标签；本轮不编造此类用户数据。
