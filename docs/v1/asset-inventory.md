## 3. 现有角色表现能力

`person(ctx, x, y, size, color, index, mood)` 使用 `index % 12` 选择造型。12种配置包括基础发型、侧发髻、帽子、长发、卷发、鸭舌帽、双发髻、灰色头饰、毛线帽、侧辫、头带/围巾、蓬松卷发等程序轮廓差异；另叠加4种肤色、4种发色、部分眼镜与服装线条，服装主色由调用方传入。这些是共享结构上的组合差异，不把组合数扩写为额外角色数量。

游戏的选中人物卡、已入座人物和候场人物都通过 `level.people.indexOf(person)` 传入造型索引，没有通过稳定角色ID查找固定造型。因此：

- 单关最多8人，实际关卡人物索引只覆盖0–7；绘制器能画出的8–11号造型不等于已经在真实关卡中绑定使用，装饰插画可使用这些索引。
- 同一个角色跨关卡若人物数组顺序变化，造型就可能变化。作者内容中12个固定姓名/ID不等于已完成12个跨关一致的视觉身份。
- `mood === 'conflict'` 使用皱嘴，其余值共用微笑。pending、neutral、satisfied没有各自独立的表情绘制分支。
- 页面另有选中底色/描边、冲突感叹号、满足条件对勾；它们是界面反馈，不是独立的人物姿态、情绪插图或庆祝动画。

后续需要完成稳定角色ID到造型的映射、跨关一致性检查、每角色5种状态的具体设计与可辨识性评审，再记录不同屏宽和真机上的视觉验收。当前不能标记为“12角色×5状态专业美术已验收”。

## 4. 合成音频清单与实测文件信息

生成源码：`scripts/generate-audio.py`。输出目录：`assets/audio/`。脚本通过数学正弦波、二次谐波和包络合成，不读取外部采样；音乐音符序列及音效基准音写在源码中。生成脚本依赖Python标准库，无外部声音包。本次未执行生成脚本覆盖资源。

现存13个WAV均为 **22050 Hz、单声道、16-bit PCM**。以下时长由WAV帧数读取，文件大小含文件头。

| 文件 | 时长 | 大小（字节） | 声音来源/去重情况 |
| --- | --- | --- | --- |

| `music-garden.wav` | 12秒 | 529244 | 脚本garden音符序列，独立波形 |
| `music-cinema.wav` | 12秒 | 529244 | 脚本cinema音符序列，独立波形 |

合计 **1,730,172字节**；完整文件SHA-256去重后共 **10种不同内容：3音乐＋7音效**。完全相同的三对为 `select/hint`、`undo/open`、`reset/close`。这与脚本音效使用 `base = 64 + index % 5` 的重复音高规则一致。短音效没有额外区分波形；完成与领取音效追加了两个音符。哈希不同只表示文件不同，不证明玩家能听出区别。

脚本对完整音频首尾施加包络；`ambience` 参数虽存在，但未参与合成计算，不能据此声称另有环境声轨。音乐文件属于可重复播放的短合成片段，不等同于已经听感验收的无缝循环音乐。

播放接入可见 `src/services/audio.js`：3场景音乐路径、10种音效名称白名单、音乐循环及音量设置；浏览器与微信分别通过 `src/platform/browser.js`、`src/platform/wechat.js` 创建音频对象。存在这些调用不证明已完成所有设备上的解码、后台恢复、混音或听感联调。
