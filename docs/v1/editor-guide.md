# 本地原创关卡编辑器

“座位创作室”是独立的浏览器关卡编辑器，采用奶油色与森林绿的左右分栏界面。它只保存本机草稿、响应用户操作下载 JSON，不会修改作者源文件、更新关卡清单或将作品发布到游戏。界面、帮助、错误提示和使用指南均为中文；数据字段和引擎 API 保持原样。

## 接入约定

- `/editor` 返回 `tools/editor/index.html`。默认开发地址为 `http://127.0.0.1:4173/editor`，端口以主预览服务的配置为准。
- 使用现有简单 CommonJS 打包器，将 `tools/editor/entry.js` 打包为 **`web/editor.bundle.js`**，通过 **`/editor.bundle.js`** 提供。HTML 已使用该绝对脚本路径。
- 浏览器依赖图只有 `tools/editor/entry.js`、`tools/editor/model.js` 和 `src/core/engine.js`。所有导入均为静态相对 CommonJS 导入，不依赖 `fs`、Node 全局变量、JSON 加载器、作者内容生成脚本或第三方包。
- 构建、服务路由与菜单入口由主流程接入。编辑器入口只应放在浏览器预览的侧栏或菜单中，不加入微信生产游戏菜单。本交付未修改构建脚本、package、游戏代码或生成的 bundle。
- HTML 与 JS 应返回正确的 MIME 类型。页面 CSP 允许同源脚本和内联样式，禁止外部连接及 eval。无外部字体、图片、账号、凭据或遥测请求。

## 编辑流程

初始示例取自原有原创关卡 1“车窗里的云”的独立快照，ID 改为 `custom-001`、类型改为 `original`，移除原参考答案。编辑示例不会改动原关卡。

1. 在“关卡信息”编辑标题、关卡 ID、章节 ID、章节编号与介绍。文本字段在完成输入并离开字段后生效。ID 会去除首尾空白、转小写，并将连续空白替换为连字符；须以英文字母或数字开头，仅含英文字母、数字、`-`、`_`，最多 64 个字符，不能使用保留对象属性名。章节编号为 0–99，与章节 ID 独立。
2. 选择“增删座位”，点击空格添加座位，点击已有座位移除。默认网格为 4 列 3 行，行列各可设为 1–8，最多 **12 个有效座位**，支持已发布的 3×3 九座关卡及 4×3 十二座布局。缩小网格不能隐藏已有座位。新增座位使用未占用的 `sN` ID，不自动生成标签或规则；删除座位会删除其相邻连线。
3. 选择“查看座位”或使用“当前座位”下拉框，编辑座位名称、标签与区域。标签支持中英文逗号分隔。“涂改标签”会在点击座位时添加或移除输入的标签。英文标签和区域值区分大小写，原有 `window` 等数据值不被翻译。所有用户文本通过 `textContent` 显示，HTML 标记仅作为普通文字。网格显示尺寸不写入 JSON，恢复时会自动扩展到容纳所有座位。
4. 点击“生成同排左右相邻连线”，将全部相邻关系替换为同一行、列坐标恰差 1 的座位对。这是明确的用户操作，增删座位不会自动补线。也可以选择座位 A/B 添加任意双向相邻关系，或点击连线标签将其移除。自连、未知座位、重复和反向重复连线均被拒绝。
5. 最多添加 **8 位人物**。选择人物后编辑姓名、ID 与规则。改名会同步更新其他人物规则中的目标 ID；移除人物会移除以其为目标的规则，保留其他规则。支持 `tag`（需要标签）、`notTag`（避开标签）、`zone`（指定区域）、`adjacent`（人物相邻）、`apart`（人物不相邻）、`emptyNeighbor`（身旁留空位）。人物关系的目标必须为另一位已存在人物。新增规则从可编辑的标签规则开始，由作者明确修改类型、值或目标及描述，不会从解法自动推断整套规则。

## 试坐与求解

选择人物后，在“试坐预览”模式点击座位。移动到已有人的座位时，如果所选人物已有座位，两人交换；否则原占用者回候场区。再次点击所选人物已坐的座位可将其移回候场区。“清空试坐”不影响关卡数据。

验证直接调用现有 `engine.evaluate(level, placement)`，逐人逐条显示“待安排 / 不满足 / 已满足”。修改关卡会清空试坐安排，避免保留失效位置。

“求解”调用编辑器的 `model.solveLevel(level)`，以共享引擎的评估结果为规则依据，重新搜索全部座位，仅替换预览，不修改规则或存入参考答案。求解和导出至少需要一位人物，且座位数不少于人物数。

搜索达到 **25,000 次候选评估或约 1.5 秒**时停止，二者以先到者为准。达到预算上限代表“尚不能判断有无解”，不是“无解”；此时可修改布局或补充明确规则后重试。该限制同时用于预览求解和作者答案导出。共享引擎 API 未修改，也不据此保证唯一解或难度等级。

## JSON 与本机草稿

展开“导入与导出 JSON”，粘贴一个关卡对象或选择不超过 256 KiB 的 `.json` 文件。格式错误、未知规则、无效规则值、未知人物或相邻目标、归一化后重复 ID、座位重叠、越界坐标、超过 8 人或 12 座的内容会在替换前被拒绝。失败不会破坏当前草稿。

导入参考答案时先校验其中 ID，再移除答案，避免直接信任外部答案。导入内容会规范化为 `kind: "original"`、`revision: 1` 的独立草稿，不保留其他发布元数据。

- **导出到文本框**：生成结构校验通过、不带答案的 JSON，不将草稿标记为已下载。
- **下载草稿 JSON**：下载 `<id>-draft.json`，不包含 `reference`。允许保存尚未解决的规则冲突，结构校验通过不代表一定有解。
- **求解并下载作者 JSON**：明确运行求解，下载 `<id>.json`，顶层 `reference` 为经过引擎验证的人物 ID → 座位 ID 映射。无解或达到预算上限时不导出答案；不会复制外部参考答案或据解法添加规则。

每次提交编辑后，草稿保存在当前来源的 `localStorage` 键 `today-we-sit.editor.draft.v1`。重新打开会恢复草稿。草稿可暂时没有人物或座位，正式导出仍须满足非空与座位数量要求。状态栏区分本机保存与已发起下载；有未下载修改或未完成输入时，离开页面会触发浏览器提示。浏览器无法确认用户最后是否保留下载文件，请自行妥善保存 JSON。

替换草稿、载入示例及“清除本机草稿”前均有确认。“清除本机草稿”只删除本编辑器的存储键，清空试坐与 JSON 文本，恢复未保存的示例；再次编辑会建立新草稿。存储不可用时会显示提示，仍可下载。浏览器草稿仅属于当前来源和浏览器配置，不代替文件备份。

## 验证

运行 `node --test tests/editor.test.js tests/engine.test.js`。

测试覆盖错误导入、未知及重复 ID、尺寸上限、网格增删、相邻关系、人物关系同步、试坐交换、文本原样往返、显式答案导出、九座/十二座布局和预算耗尽。VM 沙箱测试编译相同的相对 CommonJS 依赖图，在没有 Node 全局变量或内置导入的情况下运行模型和求解器。

浏览器检查项：增删座位、涂改标签、建立及删除连线、含 HTML 字符的普通文本名称、人物与关系规则、手动冲突、求解、JSON 导入导出、错误导入不覆盖草稿、重新载入草稿、清除草稿。游戏发布、微信手机体验与关卡编排仍由各自流程审核。
