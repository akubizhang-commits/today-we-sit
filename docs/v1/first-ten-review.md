# 前十关学习序列评审

## 检查范围与结论

本次按 `content/manifest.json` 的主线顺序，检查 `content/authoring/levels.json` 中前十关；核对实际人物、座位、规则、作者参考解，并用现有引擎重新求解及穷举全部合法单人单座分配。没有更改关卡 ID、规则、相邻图、参考解、进度结构或应用逻辑，没有读取玩家数据，也没有进行浏览器或人工试玩。

十关的作者参考解和重新求得的解均通过 `engine.evaluate()`。每关最多检查 720 种完整分配；这份解数是有限范围内的完整计数，不是估计。程序检查不能证明玩家理解、操作顺畅或难度合适，人工 QA 仍待验收。

教程的主要问题是事件错位：第 5 关实际没有 `adjacent/apart` 规则，却先等待只在点选关系规则角色时出现的 `relation`；第 3、4 关原本分别要求出现冲突、换位或撤销，直接摆对的玩家也会留下教程。此次保留原步骤 ID，修复自然正确路径不能结束提示的问题，并将教程中的“乘客 / 这个人 / 两个人”统一为“伙伴 / 小动物”。

## 前五关提示与真实事件

| 关卡 / 原步骤 ID | 当前提示意图 | 可推进的已验证事件 | 高亮目标 |
| --- | --- | --- | --- |
| 1 `level-1:select` | 点选小动物，读它想坐哪里 | `select` | `person` |
| 2 `level-2:place` | 点空座入座，分清靠窗与避开窗边 | `place` | `seat` |
| 3 `level-3:conflict` | 看后排和相邻条件，同排左右紧挨才算 | `relation`、`place`；兼容原 `conflict` | `rules` |
| 4 `level-4:swap-or-undo` | 需要调整时才换位或撤销；摆对继续入座 | `swap`、`undo`、`place` | `swap` |
| 5 `level-5:relation` | 点选伙伴，留意空邻座条件 | `select`；兼容原 `relation` | `person` |
| 5 `level-5:emptyNeighbor` | 点选真正需要空邻座的伙伴 | `emptyNeighbor` | `rules` |

`relation`、`emptyNeighbor`、`rule:<type>` 由现有 `selectPerson()` 根据被点选角色的真实规则发出；发生实际布局变化后，现有 `place()` 才发出 `place/swap`。教程不凭评估结果、渲染、高亮或一个不存在的“我知道了”事件完成步骤，也不新增必须先犯错的要求。

第 5 关历史步骤名 `relation` 仅为兼容已保存 ID 而保留，当前文字不再让玩家找不存在的人物关系。点选有空邻座需求的小动物时，应用可以连续发出 `select` 与 `emptyNeighbor`，两步可以在这次真实点选中完成；这是已核对条件的事件链，不是定时跳步。

第 3、4 关允许正常入座结束操作提示，表示已经尝试本关操作，不代表程序证明玩家理解所有规则或完成教学考核。关卡是否成功仍完全由原规则引擎判断。历史 `conflict/undo/relation` 事件、已保存的 `completedSteps` 和重复事件幂等行为均保留。

## 高亮 API 与第 6–10 关边界

新增纯读取接口：

```js
getFocus(levelNumber, progress)
// → 'person' | 'seat' | 'rules' | 'swap' | null
```

接口与 `getText()` 共用当前步骤查询。当前步骤完成后不再指向它；前五关结束、第六关起及未知关卡返回 `null`。该值是语义目标，不是屏幕坐标，也不承诺当前存在可点的换位或撤销按钮。主 UI 根据布局解析目标，无可用目标时可不画高亮。调用不会修改进度，不负责动画、遮罩、输入锁定或生命周期。

第 6–10 关不再增加必须操作的步骤队列。按已有 `getText(levelNumber, session, result, progress)` 的 `session.ruleType` 可选入口，提供轻量的首次规则说明：第 6 关区分不相邻与隔排；第 7 关结合两组相邻与中排空邻座；第 8 关提醒三对满座时利用区域条件；第 9 关逐一核对两个空邻需求；第 10 关提示后排空位与两组相邻的组合。只使用该关实际存在的规则类型，不引入气味、体型、温度或新操作。

这些规则阅读说明沿用 `rule:<type>` 首次阅读标记：确认过的类型不重复弹出，普通 session 不凭空出现后五关任务。为了让开场提示不依赖规则阅读器传入 `session.ruleType`，另提供独立的纯读取接口：

```js
getIntro(levelNumber)
// 第 6–10 关返回一条不超过 35 字的提示；其余输入返回 ''
```

## 弱点与待人工检查

1. **第 3 关一次引入两种概念和两排布局。** 原本以“制造冲突”作为入口并不能分清区域与相邻。此次提示先说后排，再说同排紧挨；是否仍需更清楚的区域标识，需要实际观察首次玩家。
2. **第 5 关同时增加座位、规则数和空位概念。** 不能仅看完成时有三个空位就认为空邻座容易理解。需要观察玩家能否指出真正与伙伴相邻的那一格，而不是任意空格。
3. **第 7 到第 8 关的阅读负担明显增加。** 从 5 位、8 条规则增加到 6 位、11 条。第 8 关虽是唯一解，仍有更多关系需要交叉阅读；本次未因此降低题目语义或删除条件。
4. **后段部分条件是单独可推导的重复线索。** 逐条临时移除规则并重新穷举后，第 8 关知夏的 `apart`、第 9 关小竹的 `apart`、第 10 关雨点的 `apart` 均不改变完整解数；第 10 关星子的 `emptyNeighbor` 单独移除也不改变解集。这说明“过关”不一定证明玩家主动用了每一条概念。单条冗余不代表可以同时删去多条；作者内容未修改。
5. **非唯一解必须友好接受。** 第 3、4、5、7、9、10 关均有两个解，作者参考布局只是其中之一。教学提示不应把某个固定 ID 当作唯一正确位置。
6. **术语仍需全内容复核。** 本次教程已统一伙伴/小动物；第 9 关作者 `designIntent` 仍有“成对乘客”，属于内容负责方可继续清理的作者文案，本次未越界修改。
7. **提示与高亮不是人工验收。** 仍需检查 320px 等小屏上的两行提示、完整规则阅读、拖动与点选两条路径、换位说明的可发现性、提示辅助通关后的再进入，以及不同年龄玩家对“不相邻”和空邻座的理解。没有收集通关时长、误触率、流失率或真实用户反馈，不作这些指标的改善承诺。
