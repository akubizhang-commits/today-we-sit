# 给喵挪个窝 · 动物情绪反馈

## 已确认范围

在现有原创动物基础上，增加开心、难过、困倦、委屈、生气、期待、惊喜七种情绪。情绪是规则反馈与角色表演，不增加好感值、饥饿、惩罚、隐藏条件或收费。保持关卡、角色身份、相邻关系和存档结构不变。

## 情绪含义与顺序

- 未入座：期待安排。
- 已入座但朋友未入座、空邻位尚不能判断：期待等待，明确提示等待的伙伴或判断时机。
- 明确违反避开标签或不相邻条件：可爱的生气。
- 未满足想要标签、区域、相邻朋友或空邻位：委屈。
- 所有偏好满足：开心；午睡屋表现为安心困倦，仍保留满足符号。
- 从不满足/等待变成满足：短暂惊喜，再回开心或困倦。
- 从满足变成冲突：短暂难过，再回对应的委屈或生气。

多条条件冲突时，表情原因采用规则列表第一条冲突，完整偏好仍逐条展示。不能把未知关系判成生气，也不能根据角色物种推断额外禁忌。情绪原因直接来自原规则文字，不编造新偏好。

## 开发拆分与接口

1. `features/emotions.js`：纯规则到情绪映射、瞬时反应以及时间采样。临时反应持续1500ms，前65%显示过渡表情，之后回到稳定表情；只在内存中存储。
2. `app.js`：移动、交换、撤销、重置后重新计算；进入关卡清空反应。动画约30fps，结束后停止额外重绘；不触发存档写入。
3. `ui/draw.js`：保留原角色身份与外形，用脸、耳朵和物种小动作表达情绪。绘制函数接收情绪和动作相位，不读取时钟或随机数。
4. 游玩区/偏好面板：头像、情绪名称、原因同时呈现；偏好面板提供大头像，保留每条规则和完整原因，不能只靠颜色或表情猜状态。
5. 完成画面：展示本关所有伙伴；巴士开心出发、食堂抱小碗、午睡屋安心休息。过渡反应后回稳定表情。
6. 验证：纯规则测试、生命周期与存档隔离测试、全套回归、表情样张及小屏检查。

“减少动效”开启时使用静态稳定表情。持续静置不会让动物越来越生气，不新增情绪音效，遵守既有声音设置。

## 验收边界

使用隔离内存进度生成离线预览，不操作用户的现有浏览器存档。程序检查不替代微信真机观感与玩家对情绪辨识度的试玩验证。

## 本轮结果

12种动物均具备7种情绪和基础平静表情；完整表情与动作尺寸对照图位于`assets/marketing/emotions/`。416项测试通过（含原生Canvas像素检查），浏览器与微信本地候选构建成功。已离线检查320×568带安全区的偏好面板和午睡完成画面。真实玩家能否快速辨识细微表情，仍需试玩确认。

## 过关节奏调整

完成最后一步后，场景停留2400ms展示伙伴表情，再自动出现结算。期间仅提供‘查看结算’按钮，可提前继续；暂停换位、撤销等关卡操作。完成进度即时保存，不等过渡结束；后台时间不消耗这段停留，减少动效模式同样保留阅读时间。新增3项回归检查，全套419项通过。
