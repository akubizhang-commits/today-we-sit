# 给喵挪个位：动物世界三场景设计说明

本轮以小动物的出行、用餐和午睡构成独立的日常世界。前三章展示名依次为“萌宠巴士”“萌宠食堂”“呼噜午睡屋”。场景应有各自的空间用途、物件和行为线索，而不是只在原有人类场景上替换头像。主游戏画面由 UI 改动负责，124 道题的标题、介绍及规则描述由内容改动负责；编辑器和浏览器介绍页统一展示词汇。本说明记录设计边界与验收要求，不代表相关画面或人工 QA 已验收。

## 第一章：萌宠巴士

内部章节 ID 为 `bus`，章节编号仍为 0。表现小动物结伴出行的小巴：适合爪子攀靠的窗沿、软垫座椅、低处扶手和随身小包，让动物成为空间的使用者。车窗、车门与前后排继续给出清楚的位置线索，装饰不得遮挡座位、占用状态或规则提示。

角色文案围绕看云、观察窗外、陪伴朋友和给尾巴留一点空间展开。例如“想趴在窗边看云”可解释已有靠窗规则；“想挨着伙伴坐”对应已有相邻规则。尾巴、爪子等描写不增加碰撞范围，也不自动要求额外空位。只有明确配置 `emptyNeighbor`，才需要一个相邻空座。

## 第二章：萌宠食堂

内部章节 ID 继续使用 `garden`，章节编号仍为 1。展示为小动物共享的食堂，而非庭院野餐：低矮餐桌、适合不同角色的小碗、取餐台、窗边和暖灯构成场景。餐具大小属于美术表达，不改变座位数量或角色占用。窗边区域与取餐侧应通过空间物件区分，不只依靠颜色。

角色文案可描述喜欢窗边、想坐暖灯附近、希望挨着饭搭子，或给餐篮留空。这些偏好必须落实到已有标签、区域、人物关系或空邻座规则。食物香气、挑食、进食速度等可以成为叙事，但本轮没有气味扩散、饮食冲突、取餐距离或先后顺序机制。

本轮 `shade` 在所有场景统一显示为“遮光位”，食堂也不另称“树荫”或“阴凉位”，以免同一值产生多种规则解释。可以用窗帘、顶棚或软隔板解释遮光；遮光不表示温度较低。`garden` 作为区域值显示为“窗边区”，与其作为章节 ID 时的“萌宠食堂”按用途分别映射。

## 第三章：呼噜午睡屋

内部章节 ID 继续使用 `cinema`，章节编号仍为 2。展示为安静的午睡空间：窝垫、窗帘、晨光照入的区域、里侧小窝，以及代表轻音乐的物件。应摆脱银幕、影院座排和观众席的叙事；原有几何位置与相邻图仍沿用，不因场景更名而改变。

角色文案可围绕喜欢晨光、想在遮光位蜷起来、想靠近或避开轻音乐、希望窝旁空一点展开。呼噜声、睡姿和绒毯是角色及环境描写，不参与音量、睡眠状态或舒适度计算。晨光区不意味着更暖，里侧窝不意味着更安静；若需要这类玩法，须另行定义规则，而不能靠文案暗示。

## 展示映射与兼容约定

| 章节 | `bus` | 萌宠巴士 |
| 章节 | `garden` | 萌宠食堂 |
| 章节 | `cinema` | 呼噜午睡屋 |
| 标签 | `speaker` | 轻音乐 |
| 标签、区域 | `screen` | 晨光区 |

`window`、`door`、`serving` 等仍表示原有的靠窗、门旁、取餐侧；前后排、左右位置和行号也保持原有含义。所有映射只用于展示，不参与规则运算。

编辑器网格、标签/区域说明和规则验证结果显示新称呼。可编辑文本框继续展示真实内部值，并附上场景称呼，避免作者误把中文名称写进规则值。既有下拉框只改变展示文案，不改变选项 `value`；自定义角色、座位名称和未知标签、区域、章节值均按原值显示，不能误归类为内置场景。作者填写的自由规则说明不被展示映射自动替换。JSON 导入、导出中的键和值仍使用原有约定。

关卡 ID、章节 ID、存档键和格式、座位坐标、标签集合、区域归属及显式相邻图不因主题升级而迁移。人物仍是一人一位，支持的规则仍为 `tag`、`notTag`、`zone`、`adjacent`、`apart`、`emptyNeighbor`。标签取值与区域匹配、相邻及不相邻判断都保持原样。动物物种和喜好是角色呈现，不能凭物种自动推断规则，也不应将某种动物写成必须具有某种偏好。

## 未来机制：可独立设计，本轮未实现

以下是以后可单独立项的方向，不属于当前功能，不进入本轮规则说明或发布承诺：

- **体型占位**：若未来引入大体型占两格、小体型共享窝等玩法，需要明确覆盖格、碰撞、换位和合法布局，并同步扩展求解器及编辑器。当前所有角色仍只占一个座位，图像大小不影响判定。
- **气味**：需要明确气味来源、范围、阻隔、偏好及冲突的计算方式。本轮没有气味字段，也不会根据食物或物种触发效果。
- **温度**：需要独立定义温区、变化方式、角色需求及可视提示。本轮遮光、晨光、暖灯等仅为既有离散标签的展示词，没有冷热值、时间变化或温度模拟。

新增机制应单独评估内容版本、存档兼容、规则阅读器、求解预算和无障碍提示，不能把机制变更隐藏在主题文案更新中。

## 人工验收与权利边界

人工 QA 仍待验收。验收时至少确认：三个场景用途和美术语言有区分；全部关卡的文案、场景物件与真实标签位置一致；“相邻”仍依据显式连线；无新增机制的误导性暗示；长中文文案与角色图像不会遮挡交互；旧存档能进入对应关卡；编辑器选项保留内部值，自定义值原样显示。程序校验与求解成功只能证明相应数据和规则检查通过，不能替代真机体验。

独立动物世界是设计方向，不是不侵权保证。角色造型、场景构图、名称、文案、音频和其他素材仍需记录来源并接受发布前权利审查；不能因采用原创绘制、动物题材或改变主题就认定不存在侵权风险。本说明不作权利清理完成或可直接上线的结论。
