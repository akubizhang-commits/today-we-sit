# 《给喵挪个窝》v1.4「看图就能玩」PRD

版本：v0.2 评审稿（吸收产品/工程两轮评审）· 日期：2026-09-28 · 状态：已批准（2026-09-28）
配套：[开发设计](2026-09-28-glanceable-play-tech-design.md) · [评审回应](2026-09-28-glanceable-play-review-response.md)

**一句话目标：进关不读长文、摆一下就知道谁高兴；想清楚再动手的玩家能留下爪印。**

## 1. 背景

用户反馈三个问题：①每关文字太多；②推理性不强、缺乏乐趣；③过关奖励吸引力不足。本轮解决①，并对②做防护、给出量化体检；③和②的新机制分别留给方向 C、B。

现状证据（磁盘统计，2026-09-28）：

| 事实 | 数据 |
|---|---|
| 进关自动弹出多页开场故事 | 114 关主线/每日 + 12 关小剧场全部有 `story`；平均约 180 字、3 页 |
| 心愿以整句台词呈现 | 如「我想和阿陶同排、左右紧挨着看草图。」，另有冲突/等待反馈句 |
| 座位下写文字标签 | 「1号空位 / 靠窗」「6号小窝 / 多标签」 |
| 主线盲摆 | 摆放时表情、✓/! 全部中性；点「安排好啦」才判卷，失败计次影响星级 |
| 冗余规则 | 单条删除后解集不变的规则 162 条，分布在 64 关（工程评审实测） |
| 即时反馈下的试错强度 | 「每只随机坐进符合自身图标的空位」一次成功率 ≥25% 的主线关有 12 关；「随机修补」步数中位 88、下四分位 22（产品评审实测） |

竞品参考：ITST 每条需求 ≤10 词 + 即时表情反馈；LinkedIn Queens 一句话规则 + 自动标记 + 提示只给方向；Tametsi「永不需要猜」；Picross「约束写在棋盘上」。

**本轮的已知代价（已接受）：** 星级改为只看提示后区分度下降，大多数玩家会三星；区分度由可见的爪印承担，奖励吸引力问题交给方向 C。

## 2. 范围

| 纳入 | 不纳入 |
|---|---|
| 主线 100、每日 14、小剧场 12（共用 `play` 画面） | 高难挑战（盲摆、交作业判题，行为与外观不变） |
| 开场、心愿、座位、提示、toast、完成与结算的呈现 | 伙伴新故事样板（开发隐藏入口，行为不变） |
| 星级改为只看提示；爪印 | 独立教程逻辑（仅同步图标） |
| 冗余规则**报告**、关卡深度体检**报告** | 实际删除规则（→ 方向 B）、新机制（B）、新奖励（C） |

## 3. 需求

### R1 进关不弹故事
- R1.1 进入纳入范围的关卡，**不自动打开**故事面板，直接显示场景与候场区。
- R1.2 标题下常驻一句话（关卡 `intro`），**≤20 字**，整行可点，打开完整故事（只读，内容保留）。
- R1.3 126 关 `intro` 逐条人工改写到 ≤20 字：保留人物与事件，不含规则信息。
- R1.4 `story.ending` 只在结算出现，**≤24 字**（现有 20 关超长，改写）。
- R1.5 故事正文与代码中所有旧流程用语（「安排好啦」「查看结算」「确认安排」等）清零。
- R1.6 「这关换了新安排」只提示一次（toast），之后不再出现。

### R2 心愿图标化
- R2.1 每条规则有一个图标和一个 ≤6 字短标签，全局统一映射（附录 A）。
- R2.2 **候场卡只显示图标**（最多 4 个，2×2；超出显示「+N」），不显示文字。
- R2.3 点动物（候场或已入座）弹出心愿气泡：每行「图标 + 短标签 + 状态」。状态用三种不同**形状**：✓ 满足、! 冲突、… 待定。
- R2.4 已入座动物头顶只显示表情，不常驻图标。
- R2.5 关系类图标 = 对方头像 + 对方名字首字 + 符号，不只靠毛色区分。
- R2.6 否定 = 同一图标加斜杠，斜杠在最小尺寸下须清晰。
- R2.7 原整句台词与冲突反馈句不在默认界面出现；只保留在完整故事和规则阅读器中。
- R2.8 **首次学习**：某个图标第一次出现在玩家面前时，候场卡下方临时显示它的短标签（每种图标一生一次，记入本机存档）。
- R2.9 同一关内任意两条心愿的短标签不得只差一个字；同一场景内指向同一组座位的规则只用一个图标（如影院「晨光/前排/第1排」合并）。

### R3 座位与场景
- R3.1 去掉座位下「N号空位」「靠窗」「多标签」等文字；座位编号只在规则阅读器中出现。
- R3.2 带功能标签（窗、门、遮光、取餐、暖灯、音箱、借还台、安静、晨光）的座位，角落画 ≤2 个图标，超出画「+」。
- R3.3 位置类规则的视觉锚点：场景地面画**不含文字**的分区色块与排线，颜色与心愿里的迷你座位图一致，使「前排 / 花园区」等在棋盘上可直接对应。
- R3.4 分区（zone）命名按场景重起，避免与标签撞字（如 garden 的 `garden/kitchen` 分区改称「花坛边 / 灶台边」，不再用「窗」「取餐」）。

### R4 即时反馈与自动过关
- R4.1 每次放置、换位、撤销、移出、移动音箱后立即评估，更新表情、状态、反应动画；反馈延迟 ≤100ms。
- R4.2 删除「安排好啦」按钮。全员满足后定格约 1 秒「都坐舒服啦！」，播完成演出后**自动进入结算**；点任意处可跳过。减少动效模式下省略演出，定格后直接结算。
- R4.3 只报告已确定的事：相邻/不相邻在对方入座前为「…」；「旁边有空」在全员入座前为「…」。
- R4.4 反馈只针对动物，不针对座位：正式关不高亮候选座位（规则聚焦关闭），拖动时不预览落点满意度。
- R4.5 保存失败时不卡关：结算页显示「没保存成功」与「重试保存」，已完成局面保留。
- R4.6 旧存档中「已摆满、等待确认」的草稿，进关即判定并按规则结算。

### R5 星级
- R5.1 没用提示 3 星；用过方向提示 2 星；用过一步提示 1 星。移动、换位、撤销、重置不影响。
- R5.2 已有首次/最好成绩原样保留、原样显示；最好只升不降。
- R5.3 本版本开始的新一轮不再记录失败；升级前已经进行中且记过失败的那一轮，按旧规则结算一次，详情里说明「按旧版规则计」。
- R5.4 所有评分说明文案改为新规则。

### R6 提示（无文字化）
- R6.1 **方向提示**（记 direction）：让一只关键动物的心愿图标和与之相关的对方头像闪烁 2 次，不出文字。
- R6.2 **一步提示**（记 answer，沿用现有权益/配额）：把目标动物和目标座位同时高亮，不写「N号座位」。
- R6.3 原「核对安排」入口删除（即时反馈已标出谁不满意）。
- R6.4 提示权益相关 toast 缩短到 ≤20 字，完整说明折叠在「了解详情」。

### R7 结算精简
- R7.1 默认只显示：标题、星级 + 爪印位、纪念画面、一句结尾、主按钮「下一关」，次按钮「重玩」「分享」。
- R7.2 评分明细、历史成绩、规则说明只在 ⓘ 中出现。

### R8 「一次到位」爪印
- R8.1 获得条件（三者同时满足）：
  1. **首次通关的那一轮**（该关此前从未有过完成记录）；
  2. 本轮未使用任何提示；
  3. 本轮**从未出现过「!」**。只移动「…」状态的动物、点错进一个仍是「…」或「✓」的座位，都不影响爪印。
- R8.2 「已出现过 !」的标记随草稿存档，退出再进不重置；重置本关不恢复资格。
- R8.3 爪印**可见**：结算的星级旁、关卡列表格子里都有爪印位——获得为实心，未获得为灰色空位；每章标题显示「爪印 N/M」。
- R8.4 第一次在结算看到爪印位时，显示一句说明：「一次都没让伙伴皱眉，就能留下爪印。」之后只在 ⓘ 中。
- R8.5 爪印不影响星级、解锁或纪念卡。升级前已通关的关卡不补发爪印（没有「首次通关」可判定），列表中显示灰色空位。

### R9 文字界面清单
- R9.1 开发设计附一张「全部玩家可见文字界面」清单，每项标注保留 / 缩短（上限）/ 删除。
- R9.2 游戏过程中的 toast ≤14 字；存档异常、广告/权益类保留完整原文但折叠显示，默认只露一行 ≤20 字。

### R10 报告（不改关卡）
- R10.1 **冗余规则报告**：每关每条「单删后解集不变」的规则，标注是否被故事/clueMap 引用、是否为该动物唯一规则。本轮不删除，交方向 B 评审。
- R10.2 **深度体检报告**：每关「单条件直接定位率」「解集大小」「规则数/动物数」「随机修补步数中位」「随机图标摆放一次成功率」；标出「即时反馈下偏浅」的关（随机修补中位 <30 步，或一次成功率 ≥25%）。

## 4. 推理乐趣的防护

| 风险 | 防护 | 性质 |
|---|---|---|
| 即时反馈让局部试错变便宜 | 如实承认：星级不再惩罚试错；**爪印是唯一的深度信号**，且可见、条件是「从未让伙伴皱眉」 | 奖励想清楚再动手 |
| 候选座位高亮等于给答案 | R4.4 正式关关闭；提示也只高亮一只动物的一个座位 | 限制信息 |
| 拖动预览 | R4.4 不做 | 限制信息 |
| 规则里有凑数条件、关卡偏浅 | R10 两份报告量化，交方向 B 重做；本轮**不宣称**推理深度已提升 | 为下一轮输入 |

## 5. 验收标准

| 编号 | 标准 | 方法 |
|---|---|---|
| AC1 | 126 关进关首帧 `storyOpen===false`、无 modal | 自动化 |
| AC2 | 首帧场景外的叙述性文字只有标题和 intro（≤20 字）；候场卡无文字（首次学习标签除外） | 自动化 + 截图 |
| AC3 | 图标映射覆盖全部 126 关（含小剧场）的全部规则；短标签 ≤6 字；R2.9 两条规则成立 | 内容校验 + 单测 |
| AC4 | 每次改动后 ≤100ms 内状态更新；全员满足后自动结算；保存失败可重试；旧「已摆满」草稿可结算 | 自动化 |
| AC5 | 星级只随提示变化；旧成绩显示不变；旧进行中失败轮按 R5.3 | 单测 + 旧档 fixture |
| AC6 | 爪印三条件、存档往返、重置、首次通关、旧档不补发 | 单测 |
| AC7 | 旧流程用语在内容与代码中出现 0 次 | grep 检查纳入测试 |
| AC8 | 挑战模式、伙伴样板行为与外观不变 | 相关测试不改且全部通过 |
| AC9 | 320/390/430 宽：图标 ≥12px（候场）/≥20px（气泡），可点区域 ≥44px；状态三形状可辨；无重叠 | 截图 + 人工 |
| AC10 | 减少动效模式下无完成演出，直接结算 | 自动化 |
| AC11 | 两份报告生成，偏浅关清单交付 | 文件存在且覆盖 126 关 |
| AC12 | `npm test`、`content:validate`、`build` 全部通过 | 命令输出 |

程序验收不代表趣味性通过。完成后建议找 3–5 位未玩过的人各玩第 1 章前 5 关，记录：是否主动点开故事；能否不问就说出 3 个图标的含义；是否提到「试出来的」；是否注意到爪印。结果写入交付记录。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 图标看不懂 | R2.8 首次学习标签；气泡始终带短标签；规则阅读器保留完整文字 |
| 小屏候场区放不下 | 12px 2×2 + 「+N」；320×568 截图验收 |
| 星级通胀 | 已接受；爪印承担区分度；写入交付说明 |
| 大量测试依赖旧行为 | 开发设计逐文件列出，改为新行为断言，不删测试 |
